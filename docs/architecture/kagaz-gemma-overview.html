Kagaz: a document app that keeps your IDs private, with Gemma doing the thinking.

Kagaz is an offline-first document vault for India: Aadhaar, PAN, certificates. We added an AI assistant that runs the app's tools for you. The key design choice: one Gemma 4 family on the phone, on a laptop, and in the cloud, behind a single switch the user controls.

1The product, in layers

Clean architecture: each feature is a module that talks to others only through interfaces, so any piece (the AI engine, the database, OCR) can be swapped without touching the screens.

2The AI architecture

The chat talks to one interface, ChatEngine. Three engines implement it. The assistant's tools are the app's own features, registered once and reused by every engine.

3One request, end to end

"Resize my passport photo for a government form." Rehearsed in a real browser: the model asked for the sizes with a form, then produced the file.

4One switch: online or offline

The user, not the developer, decides where their data goes. Turning online on shows a plain-language warning first.

5Where Gemma is used

Six jobs, one model family. Honest status on each.

Working, tested live

Chat with function calling

Gemma picks the right tool from the app's own features, fills in its typed arguments, and chains steps. Local and cloud both verified in a real browser.

Working, tested live

Vision: reading documents

Transcribes an ID-style image in English and Hindi, and can re-read every page of a scanned PDF. Quick online, slower on a laptop CPU.

Working, tested live

GenUI: Gemma writes the form

When details are missing, it generates a typed form (numbers, choices, text, dates, documents) through function calling. It does not always choose to, see the honest status.

Working

Skills: choosing tools

A router plus ai.loadSkill loads only the tool group a request needs, so a small model reads a much shorter prompt.

Built and tested, not wired in

EmbeddingGemma

Embeddings rank documents correctly by meaning, including Hindi to English. The embedding and vector-store layer exists; no screen or tool uses it yet.

Built, not yet run on a phone

Gemma 4 E2B in the APK

The Android build downloads the large LiteRT model and checks its checksum on every load. Not verified on a physical device.

6Why Gemma

The reasons, with the evidence behind each.

It can run where the data lives

Open weights, Apache-2.0, and the compact E2B size runs on a phone and on a CPU-only laptop. For an app holding Aadhaar and PAN, "the model comes to the data" beats "the data goes to the model".

Native function calling

The app's tools are exposed as typed functions and Gemma calls them directly, including names like settings.setTheme. No prompt tricks or output parsing. Structured output also passed a schema-constrained test.

It reads images, in Hindi too

One model both converses and looks at a document. Vision transcribed an English-and-Hindi ID-style image correctly, so OCR does not need a separate engine in the browser demo.

One family on device, laptop and cloud

Gemma 4 E2B locally and Gemma 4 26B on Vertex AI share the same tool schema and prompts. We tested the same scenarios against both, so switching modes does not change behavior in ways the user has to learn.

An embedding sibling for search

EmbeddingGemma, a compact multilingual embedding model, pairs naturally with the chat model for finding documents by meaning.

The honest trade-off. A small model on a CPU-only laptop is slow to give its first answer and weaker at multi-step requests. Cloud Gemma is much faster, which is why the online option exists, and why the switch is a choice, not a default.

7How we added it

Each step was forced by a real obstacle. The order matters.

  1. First plan failed on contact with Android

    The original design ran WebLLM in the WebView. On the target phones WebGPU in System WebView is unreliable (no usable adapter on an emulator), so we moved inference out of the WebView into a native LiteRT-LM plugin (ADR-021).

  2. One interface in front of the engine

    The chat's four calls became the ChatEngine interface. The native engine is a pass-through, so the confirmation cards, tool dispatch and tests did not change.

  3. The demo machine had no Apple Silicon

    LiteRT-LM ships no Intel-Mac build, so for the laptop we added an OllamaChatEngine running the same Gemma 4 E2B, plus a shared tool loop reused by every server-style engine.

  4. The tool list was too big for a small model

    Putting every tool in every prompt is costly for a small model. Skills load a group only when needed (a keyword router, English and Hindi, plus a loader tool), with a guard that rejects any tool whose skill isn't loaded.

  5. Local was too slow to demo comfortably

    We added an online mode on Vertex AI through a same-origin dev proxy, behind one switch with a data-sharing warning. Vision and embeddings follow the same switch.

  6. From chat to a real journey

    Attach documents, GenUI forms the model writes when details are missing, result cards that open the new file, and markdown in the chat.

  7. Gemma everywhere

    Online chat and vision moved to Gemma 4 on Vertex, and the earlier small fallback model was removed, so the whole app is one family: Gemma 4 E2B on the phone and laptop, Gemma 4 26B in the cloud.

8Hard problems we hit

Each was found by running the real app, not by reading code.

Solved

"The database doesn't exist in a browser"

Four problems stacked: no SQLite element mounted, a CSP blocking WebAssembly, a WASM binary one minor version away from the JavaScript that loads it, and an autosave that exported the database after every statement and silently ended the open transaction. Fixed layer by layer; the whole journey now runs in a real browser.

Solved

A look-alike tool sabotaged skills

With skills, a navigation tool called "open PDF Tools" stayed always-on. Asked to compress a PDF, the model navigated instead and then claimed it had compressed it. Moving that tool into the PDF skill fixed it.

Solved

The page reloaded mid-demo and dropped the AI

Vite discovered a lazily imported dependency, re-optimized, and reloaded, wiping the in-memory connection. Declaring those dependencies up front fixed it; found while rehearsing.

Open

The model sometimes chats instead of using the form

Asked for missing details, the model sometimes asks in plain text. More rules in the prompt made it worse in a controlled test, so we reverted them. Pass rates are reported as measured, not rounded up.
